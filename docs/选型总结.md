# 逆水小助手 · 技术选型总结（多游戏复用架构）

> 日期：2026-10-28
> 核心要求：**代码尽量复用到其他下棋（自走棋）类小程序**（金铲铲、云顶、未来新自走棋等）。
> 结论先行：采用「**通用内核 + 游戏内容包**」两层架构；UI 全部数据驱动；技术栈选**微信原生 + 云开发**（理由见 §5）。

---

## 1. 复用性分析：原型里什么是通用的

对原型 v0.13 逐模块盘点（复用度 ★越多越通用）：

| 模块/资产 | 复用度 | 说明 |
|---|---|---|
| 蜂窝棋盘（4×7 hex） | ★★★★★ | 自走棋标准棋盘，金铲铲/云顶同规格；尺寸参数化（rows×cols） |
| 羁绊实时推算引擎 | ★★★★★ | 输入「上阵棋子→各羁绊层数→激活档位」，纯规则计算，与题材无关 |
| 摆棋全套手势（长按拖拽/热区移除/换位） | ★★★★★ | 纯交互层，零业务语义 |
| 选棋弹窗 / 棋子设置弹窗 / 撤销栈 | ★★★★★ | 数据驱动，字段通用（cost/bonds/stars/items/mainC） |
| 阵容卡 + 排序筛选 + 赞踩/口碑 | ★★★★☆ | 筛选维度（84/95/彩色羁绊）需按游戏配置 |
| 图鉴四段（棋子/羁绊/装备/强化） | ★★★★☆ | 「心悟/强化符文」各游戏叫法不同 → 术语字典 |
| 赛季体系（切换器/归档/贯穿全站） | ★★★★★ | 所有自走棋都有赛季 |
| 会员体系外骨架（TabBar/我的/收藏/广告位） | ★★★★★ | 纯框架 |
| 设计 Token（宣纸底/墨字/古铜金/五阶费用色） | ★★★☆☆ | 结构通用，色值按游戏换肤 |
| 数据内容（棋子/羁绊/装备/心悟/阵容） | ★☆☆☆☆ | **每游戏一份内容包**，结构相同 |

结论：**约 90% 的代码是游戏无关的**，需要隔离的只有：内容数据、术语叫法、配色主题、少量筛选配置。

## 2. 分层架构

```
┌─────────────────────────────────────────────┐
│  游戏内容包 games/<gameId>/                  │  ← 唯一随游戏变化的部分
│  ├─ pack.json     元信息（名称/费用阶数/棋盘规格/术语字典/主题Token/筛选配置）
│  ├─ data/*.json   pieces / bonds / equipments / augments / comps / patch_notes（按赛季）
│  └─ assets/       图标素材（可选，默认印章字头像则不需要）
├─────────────────────────────────────────────┤
│  通用组件库 components/                      │  ← 全部数据驱动，禁止写死游戏词
│  board-hex / unit-grid / trait-pill / tier-badge / cost-avatar
│  filter-bar / search-box / seg-slider / sheet / push-detail / vote-pill / ad-slot
├─────────────────────────────────────────────┤
│  通用引擎 core/                              │  ← 纯 JS，可单测
│  bondEngine（羁绊推算）/ boardModel（28格状态+撤销栈）/ gesture-drag
│  seasonManager / voteStore / favStore / format
├─────────────────────────────────────────────┤
│  页面模板 pages/                             │  ← 组合组件+引擎，读当前 pack
│  home / comps / simulator / dex / me
└─────────────────────────────────────────────┘
```

**铁律：页面和组件不允许出现任何游戏专名**（侠棋/羁绊/心悟/棋子…），一律读 `pack.terms` 术语字典。这样换游戏 = 换包，零改代码。

## 3. 内容包 schema（pack.json）

```jsonc
{
  "gameId": "xq",                      // 侠棋
  "displayName": "逆水小助手",          // 小程序内品牌名
  "terms": {                           // 术语字典 —— 反例：不得在组件里写死
    "piece": "棋子", "bond": "羁绊", "equip": "装备",
    "augment": "心悟", "comp": "阵容", "carry": "主C",
    "population": "人口", "season": "赛季", "save": "保存到我的"
  },
  "board": { "rows": 4, "cols": 7 },   // 金铲铲/云顶同为 4×7
  "cost": { "levels": [1,2,3,4,5], "colors": ["#6E7680","#3F7D52","#2F6DA8","#7C50C8","#96700F"] },
  "theme": {                           // 设计 Token，对应 app.wxss 变量
    "--bg": "#F3EFE6", "--txt": "#26221A", "--gold": "#A98643",
    "--gold-dim": "rgba(169,134,67,.13)", "--card": "#FBF9F3", "--serif": "Kaiti SC"
  },
  "compFilters": [                     // 阵容页筛选按游戏配置
    { "key": "color", "label": "彩色羁绊", "test": "colorBond" },
    { "key": "84", "label": "84阵容", "test": "pop==8&&carry==4" },
    { "key": "95", "label": "95阵容", "test": "pop==9&&carry==5" }
  ],
  "seasons": [ { "id": "S4", "name": "盈虚化象", "range": "…", "current": true } ],
  "legal": "非官方工具 · 版权归网易所有" // 各游戏版权方不同
}
```

**接入金铲铲示例**：`games/jcc/pack.json` 里 terms 改「强化符文/英雄/羁绊」，theme 换深色金铲风，board 同为 4×7，cost 1-5 不变，compFilters 改成它的阵容黑话，data/ 录入对应赛季数据——**组件、引擎、页面一行不改**。

## 4. 关键抽象点（写正式代码时的硬性约定）

1. **棋子头像**：默认「首字印章圆章」渲染（当前方案），pack 可声明 `avatarMode: "seal" | "image"` 切换为图片模式——有版权素材的游戏用图，没有的用字。
2. **羁绊推算引擎** `bondEngine.calc(units[], bonds[])`：输入棋子名数组，输出 `{ bondId, count, tier, next }[]`。档位规则来自数据（`tiers: [2,4,6]`），引擎不含任何具体羁绊。
3. **棋盘模型** `boardModel`：`board[rows*cols]` 一维数组 + stars/items/mainC 附属 map + 30 步撤销栈。行列、人口规则全部读 pack。
4. **手势层**：长按 300ms 启拖、8px 阈值、顶部热区移除、`pointercancel` 纯取消——参数写在 gesture-drag 组件顶部常量，与游戏无关。
5. **赛季贯穿**：`seasonManager` 全局单例；所有集合读写自动注入 `season` 与 `gameId` 两个维度（多游戏共存同一个云环境时按 gameId 分库或分字段）。
6. **术语字典**：所有 UI 文案经 `t("bond")` 取词；筛选标签、空态文案、分享卡片措辞全走 pack。
7. **演示数据即录入模板**：原型里 `PIECES/BONDS/EQUIPS/AUGMENTS/COMPS` 五个 JS 数组的字段就是 `data/*.json` 的 schema，录入新游戏照抄结构。

## 5. 技术选型决策

| 方案 | 跨端 | 复用方式 | 团队成本 | 生态 | 结论 |
|---|---|---|---|---|---|
| **微信原生 + 云开发** | 仅微信 | 按上述内容包抽象；换游戏=开新小程序项目复用 components/core/模板目录 | 低（原型即规格） | 云开发免运维免备案 | ✅ **首选** |
| Taro（React） | 微信/抖音/支付宝 | 组件天然 npm 包化 | 中（需重写原型为 JSX） | 好 | 备选：确有多端诉求再迁，内容包 schema 不变 |
| uni-app（Vue） | 多端含 App | 同上 | 中 | 好 | 同上 |
| H5 + web-view | 全端 | 最高 | 需自建后端+备案域名 | — | ❌ 违背「轻工具快速上线」 |

选原生的理由：① 目标用户 100% 在微信（游戏社区在微信群）；② 云开发让数据热更新零后端成本；③ 原型交互（手势/弹层）可直接按规格翻译成 WXML，无框架转译损耗；④ 复用诉求本质是「快速开同类小程序」，目录级复用 + 内容包已满足，不必上框架。若未来要出抖音版金铲助手，再评估 Taro 迁移——**内容包 schema 与引擎是跨框架的，迁移只动组件层**。

## 6. 正式工程目录（按此搭建）

```
nixiao/                          # 侠棋项目（第一个实例）
├─ app.js/json/wxss              # 读 pack.theme 注入全局变量
├─ games/xq/                     # 侠棋内容包（pack.json + data/*.json）
├─ core/                         # bondEngine / boardModel / seasonManager / stores
├─ components/                   # §2 组件库（全部带 properties，无游戏词）
├─ pages/home|comps|sim|dex|me
├─ cloudfunctions/               # 数据读写（自动注入 season/gameId）、票数去重、登录
└─ utils/
future: games/jcc/ → 新项目复制 core+components+pages，换包即用
```

## 7. 新游戏接入清单（目标：一天内出可用的姊妹版）

1. 复制工程，删除 `games/xq/`；
2. 写新 `pack.json`（术语/主题/棋盘规格/筛选配置/免责声明）；
3. 按五张表 schema 录入该游戏当前赛季数据（演示数据结构即模板）；
4. 改 `displayName` 与 TabBar 文案（读 pack）；
5. 提审（注意该游戏版权方的命名风险）。

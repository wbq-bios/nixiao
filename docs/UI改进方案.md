## A 组 · P0(信任与门面,先做)

### A1. 摆棋"重置"加确认 + 降权
- **改什么**:点"重置"先弹确认框;确认后 toast 明说"已重置 · 可撤销";重置按钮视觉降级。
- **在哪改**:`pages/sim/sim.wxml`(ops 行 + 新增确认弹窗)、`sim.js`(onReset 拆成 onResetAsk/onResetDo)、`sim.wxss`(重置改灰字)。
- **怎么改**:复用全局现成的 `modal-mask/modal` + `btn-rm/btn-ok` 样式,文案"清空当前棋盘?可在撤销栈恢复";确认后才执行现有 boardModel.snapshot+清空逻辑(撤销栈本来就有,补承诺)。
- **验收**:误点重置→弹窗拦截;确认后 toast 出现"可撤销"字样;撤销一步能完整恢复;重置按钮明显弱于"示例"。
- **体量**:小(≈30 分钟)。

### A2. 首页 masthead 重排(全 app 门面)
- **改什么**:`home.wxml` masthead 区重排——
  1. sub 行三段杂讯("今日热荐 XXX / 棋子随赛季更迭 / 演示数据")删掉,换一句品牌副标:**"备课 · 快查 · 复盘"**(产品定位原文);
  2. "今日热荐"从 masthead 撤下,改为热荐卡左上角小徽章;热荐卡内标题保留(masthead 大标题不再与它逐字重复);
  3. "演示数据"统一为全 app 右上角固定小角标样式(`.demo-badge`,首页/阵容/图鉴三处同一位置同一词),消灭三种说法。
- **验收**:首屏第一眼只有 赛季卡 + 品牌标题 + 一句副标 + 热荐卡(带徽章);任何地方不出现折行的标题。
- **体量**:小-中(≈1 小时,含三页角标统一)。

## B 组 · P1(一致性与名实)

### B1. 图鉴全量立绘(已拍板)
- **现状**:60 个棋子 art 字段全部有值(已验证 60/60),列表第 1 行显示印章是因为**首图未下载完时提前触发了加载失败回退**。
- **改什么**:
  1. 头像改"双层渲染":印章字永远垫底,立绘 image 绝对定位盖上层——下载中显示印章,加载完成立绘淡入覆盖,失败才保持印章(现在失败的行会变空白圆);
  2. 写一个批量检测脚本:逐个验证 60 个 art URL 返回 200,输出失败清单(若有缺失路径,给你清单去补截图);
  3. 图床大图优化:立绘原图 1-2MB/张,列表场景加载慢——后端加 `sharp` 生成 200px 缩略图路由(`/art/thumb/...`,缓存),列表用缩略图、详情用原图。
- **在哪改**:`dex.wxml`(双层)、`dex.js`(onArtErr 保留)、`backend/src/index.js`(+缩略图)、新增 `pipeline/check_art.py`(URL 批检)。
- **验收**:图鉴列表全部为真实立绘、无印章混排;断网/缺失时回退印章不裂图;列表立绘加载 <1s。
- **体量**:中(≈2 小时,含缩略图)。
- **注意**:全量立绘=图鉴/详情用真图;**摆棋蜂窝格与阵容卡条仍保持印章字**(43px 格子里立绘不可读,这是"远看是字、近看是画"的分层,不是没做完)。

### B2. 详情页"阵容站位"名实不符
- **两个方案,推荐 B2-乙**:
  - **B2-甲(最小)**:标题改"阵容构成",一行代码;
  - **B2-乙(推荐)**:详情页渲染**只读小蜂窝**——摆棋页的蜂窝渲染逻辑复用,按 comp 数据 front/back 摆进 28 格(主C金圈逻辑现成),格子尺寸缩小到 ~60%,玩家看到真实站位而非名单。
- **在哪改**:`pages/detail/detail.wxml`(站位卡替换)、`detail.js`(comp 数据 → 28 格数组,复用 sim 的 rowsDef 顺序)、`app.wxss`(蜂窝样式提为全局类,供 sim/detail 共用)。
- **验收**:详情页出现小蜂窝棋盘,主C金圈、前后排位置正确;缩放正常不溢出。
- **体量**:中(≈2 小时)。

# 逆水侠棋小程序首页设计稿

> 文档版本：V1.0\
> 状态：首页视觉与交互规范已确认，待结合微信开发者工具进行联调验收\
> 设计方向：现代极简、浅色背景、清晰卡片、少量金色点缀\
> 参考原则：参考「金铲小助手」的信息层级与功能组织方式，重新设计逆水侠棋的视觉，不直接照搬其品牌资产。

------------------------------------------------------------------------

## 1. 设计目标

首页需要让用户快速完成以下任务：

1.  浏览当前赛季与版本推荐。
2.  快速进入阵容大全、侠客图鉴、羁绊查询、装备查询、模拟摆阵。
3.  浏览今日推荐和热门阵容。
4.  横向查看阵容中的侠客。
5.  查看侠客与羁绊详情。
6.  收藏感兴趣的阵容。

设计优先级：

-   信息清晰、操作路径短。
-   阵容卡片结构统一，今日推荐与热门阵容遵循相同的信息顺序。
-   长标题、长作者名、长羁绊名不能导致控件挤压、错位或横向溢出。
-   不展示当前业务没有的数据，例如场次、胜率、平均排名、登顶率等。

## 2. 首页信息架构

首页从上到下分为以下区域：

1.  顶部品牌与赛季区
2.  搜索区
3.  版本推荐 Banner
4.  快捷功能入口
5.  今日推荐
6.  热门阵容
7.  底部导航

### 2.1 顶部品牌与赛季区

包含：

-   「逆水侠棋」品牌标题与副标题。
-   当前赛季选择器。
-   微信小程序右上角系统胶囊区域按平台规范保留。

规则：

-   品牌标题允许使用具有武侠气质的展示字体；正文优先使用清晰的系统字体。
-   赛季选择器展示当前赛季标识与赛季名称。
-   赛季切换后，首页阵容与相关内容应跟随当前赛季刷新。

### 2.2 搜索区

搜索提示示例：

`搜索侠客、羁绊、装备、阵容...`

规则：

-   搜索框高度固定，圆角与卡片体系一致。
-   提示文案过长时省略，不撑开页面。
-   点击后进入搜索或相应的查询流程。

### 2.3 版本推荐 Banner

内容：

-   版本推荐标题，例如「版本强势阵容」。
-   当前赛季简短说明。
-   「查看详情」按钮。
-   可选轮播指示器与角色背景图。

规则：

-   标题最多两行，副标题最多一行。
-   文案区域与背景角色图分离，避免文字覆盖关键人物面部。
-   背景图仅作为视觉内容，不能影响按钮的点击区域。
-   没有实际轮播数据时，不应展示虚假的轮播状态。

### 2.4 快捷功能入口

建议入口：

  入口       说明
  ---------- --------------------
  阵容大全   浏览和筛选阵容
  侠客图鉴   查看侠客信息
  羁绊查询   查询羁绊及效果
  装备查询   查看装备及合成路线
  模拟摆阵   自由搭配阵容与站位

规则：

-   各入口宽度尽量一致。
-   图标、标题、副标题垂直排列。
-   窄屏时优先压缩副标题显示长度，不缩小主要标题字号。
-   点击区域覆盖整张入口卡片，保证触控面积。

## 3. 今日推荐与热门阵容卡片

今日推荐与热门阵容复用相同的信息结构。热门阵容可以采用更紧凑的头像尺寸，但不能改变信息顺序。

### 3.1 卡片结构

每张阵容卡片由三部分组成：

1.  标题行
2.  侠客头像横向滚动区
3.  羁绊标签区

不展示额外的核心侠客说明、羁绊效果摘要、场次、胜率或排名统计。详情信息通过点击侠客头像或羁绊标签查看。

### 3.2 标题行布局

布局原则：

-   左侧：阵容图标与阵容名称。
-   右侧：作者名与一个收藏星形图标。
-   作者名靠右排列，收藏图标位于作者名右侧。
-   收藏只保留一个图标，不额外显示「收藏」文字按钮。
-   标题与右侧操作区保持独立，长文本不能挤走收藏图标。

建议结构：

``` text
┌──────────────────────────────────────────┐
│ [阵容图标] 阵容名称较长……   作者：某某  ☆ │
└──────────────────────────────────────────┘
```

### 3.3 长标题和作者名规则

**阵容标题**

-   最多显示两行。
-   超出两行时截断并显示省略号。
-   标题区域使用可伸缩宽度，允许换行。
-   右侧作者与收藏区域保持固定，不因标题长度发生横向位移。
-   标题变为两行时，卡片其余区域整体向下顺延，不允许覆盖头像。

**作者名**

-   单行显示。
-   空间不足时使用省略号。
-   作者区域设置最大宽度，避免挤压标题。
-   没有作者数据时，显示「未署名」或按产品规则隐藏作者文本；不应伪造作者名。

**收藏图标**

-   始终保持固定触控区域。
-   不因标题、作者长度改变位置。
-   未收藏与已收藏使用明确不同的图标状态。
-   点击后提供轻量状态反馈，并持久化收藏状态。

### 3.4 侠客头像横滑区

规则：

-   头像列表是独立的横向滚动区域。
-   用户在头像区域左右滑动时，切换可见侠客；页面本身仍可上下滚动。
-   不将头像横滑误做成整个阵容卡片横滑。
-   头像顺序由阵容配置决定。
-   头像过多时允许横向滚动，不挤压成过小尺寸。
-   可用轻微露出的下一个头像或细进度提示用户还有更多内容。

### 3.5 主 C 角标

-   主 C 头像左上角显示「主C」角标。
-   非主 C 头像不显示角标。
-   主 C 状态由阵容数据明确配置，不根据头像顺序、星级或费用推断。
-   角标需有足够对比度，但面积不能遮挡人物脸部。
-   若阵容有多个主 C，应由数据结构支持多个标记，而不是写死第一个头像。

### 3.6 羁绊标签

-   羁绊标签位于头像横滑区下方。
-   使用自动换行布局，允许名称较长的羁绊独立换到下一行。
-   不强制单行，也不通过缩小字体解决超长名称。
-   标签宽度由内容决定，并设置合理的最大宽度。
-   点击羁绊标签后，以详情卡片或弹层展示羁绊信息。
-   弹层中的完整名称与说明应能阅读；较长说明允许滚动。

### 3.7 侠客详情交互

-   点击头像后，以详情卡片或弹层展示侠客详情。
-   详情信息应来自当前赛季对应的真实数据。
-   弹层支持关闭；点击弹层外部是否关闭按统一交互规范处理。
-   头像本身可点击，主 C 角标不应阻断点击事件。

## 4. 页面滚动与布局行为

-   首页整体支持纵向滚动。
-   头像区域独立横向滚动。
-   羁绊标签区域根据标签数量自动增加高度。
-   阵容标题最多两行，标题变高时后续区域自然下移。
-   不使用固定卡片高度强行容纳所有羁绊。
-   页面底部内容应留出底部导航的安全空间，避免被导航栏遮挡。
-   在窄屏设备中，优先缩短作者文本，其次调整卡片内边距；不要移动收藏图标或隐藏必要操作。

## 5. 视觉规范

### 5.1 设计风格

-   现代极简。
-   暖白/浅米色背景。
-   白色或近白色卡片。
-   金色只用于重点按钮、主 C 角标、当前选中状态与少量强调。
-   正文以深墨色为主，辅助文字使用中性灰。
-   减少厚重阴影、过多描边和重复装饰。

### 5.2 建议色板

  用途        色值        说明
  ----------- ----------- --------------------
  页面背景    `#F8F7F3`   暖白浅米色
  卡片背景    `#FFFFFF`   主内容卡片
  主文字      `#1F2937`   深墨色，保证可读性
  次要文字    `#6B7280`   作者、辅助信息
  边框        `#E5E7EB`   轻量分隔线
  主强调色    `#D4A574`   金色点缀
  标签背景    `#F1F5F9`   中性浅色
  主 C 角标   `#D99535`   金橙色角标

这些色值为设计建议；落地时需与现有全局主题变量统一，避免出现多个相近但不一致的颜色。

### 5.3 圆角、间距与尺寸建议

-   主卡片圆角：12--16px。
-   卡片内边距：12--16px。
-   标题与作者区域间距：8--12px。
-   头像间距：6--10px。
-   羁绊标签间距：6--8px。
-   可点击图标触控区域建议至少 32--40px；在微信小程序中应结合 `rpx`
    与设备适配实际验证。

### 5.4 字体层级

  内容           建议字号
  -------------- ----------
  页面品牌标题   28--36px
  区域标题       20--24px
  阵容标题       16--18px
  标签与作者     12--14px
  说明文字       12--14px

正文优先可读性；仅品牌标题可使用具有武侠气质的展示字体。小尺寸文字需实际检查对比度和阅读效果。

## 6. 交互规范

  元素               操作        预期结果
  ------------------ ----------- ------------------------------
  赛季选择器         点击        展示赛季选项，切换后刷新数据
  搜索框             点击/输入   进入搜索或查询流程
  Banner 按钮        点击        进入版本推荐详情
  快捷入口           点击        跳转对应功能页面
  阵容卡片标题区域   点击        进入阵容详情
  收藏星形图标       点击        切换收藏状态
  侠客头像           点击        弹出侠客详情卡片
  羁绊标签           点击        弹出羁绊详情卡片
  头像区域           横向滑动    仅滚动侠客头像
  页面内容           纵向滑动    浏览首页内容

收藏图标的点击区域需要独立于阵容卡片的点击区域，避免点击收藏时意外进入详情页。

## 7. 数据约定

首页只显示有真实数据支持的字段。

建议阵容对象至少具备：

``` js
{
  id: "lineup-id",
  name: "阵容名称",
  author: "作者名称",
  seasonId: "S4",
  icon: "阵容图标或占位标识",
  favorite: false,
  units: [
    {
      id: "unit-id",
      name: "侠客名称",
      avatar: "头像资源路径",
      isMainCarry: true
    }
  ],
  bonds: [
    {
      id: "bond-id",
      name: "羁绊名称",
      count: 3
    }
  ]
}
```

说明：

-   上述为建议结构，不代表现有项目已采用完全相同的字段。
-   实际接入时，应优先复用项目已有的数据模型，并添加必要字段。
-   主 C 状态应来自阵容配置。
-   收藏状态应通过稳定的阵容 ID
    或项目既有唯一键保存，不建议仅用可重复的阵容名称作为唯一标识。
-   不应虚构作者、场次、胜率或其他统计数据。

## 8. 微信小程序实现建议

### 8.1 组件划分

建议将可复用的阵容卡片拆分为组件，例如：

-   `lineup-card`：阵容卡片整体。
-   `unit-avatar-list`：侠客头像横滑区。
-   `bond-tag-list`：羁绊标签自动换行区。
-   `unit-detail-popup`：侠客详情弹层。
-   `bond-detail-popup`：羁绊详情弹层。

如果首版为了降低复杂度暂时不拆成独立组件，也应保持 WXML 层级和 WXSS
类名清晰，后续再抽取。

### 8.2 长文本 CSS/WXSS 思路

以下为样式思路，具体属性需按微信小程序 WXSS 支持情况调整：

``` css
.lineup-header {
  display: flex;
  align-items: flex-start;
  gap: 8px;
}

.lineup-title {
  flex: 1;
  min-width: 0;
}

.lineup-title-text {
  display: -webkit-box;
  -webkit-box-orient: vertical;
  -webkit-line-clamp: 2;
  overflow: hidden;
  overflow-wrap: anywhere;
}

.lineup-actions {
  flex-shrink: 0;
  display: flex;
  align-items: center;
  margin-left: auto;
}

.lineup-author {
  max-width: 88px;
  white-space: nowrap;
  overflow: hidden;
  text-overflow: ellipsis;
}

.unit-avatar-list {
  display: flex;
  overflow-x: auto;
  white-space: nowrap;
}

.bond-tag-list {
  display: flex;
  flex-wrap: wrap;
  gap: 6px;
}
```

实际开发时要验证微信小程序对
`-webkit-line-clamp`、横向滚动、触摸事件与嵌套滚动的支持情况，并在窄屏设备上测试。

## 9. 验收清单

### 视觉与布局

-   [ ] 首页各区块层级清晰。
-   [ ] 今日推荐和热门阵容的信息顺序一致。
-   [ ] 作者名与收藏图标位于标题行右侧。
-   [ ] 收藏仅显示一个星形图标，不显示额外「收藏」文字。
-   [ ] 长阵容名最多两行，不覆盖作者、收藏或头像。
-   [ ] 长作者名省略，收藏图标位置固定。
-   [ ] 羁绊名过长时能自动换行。
-   [ ] 头像数量多时可独立横向滚动。
-   [ ] 主 C 角标只在数据标记的侠客上显示。
-   [ ] 页面无横向溢出，底部内容不被导航栏遮挡。

### 功能与数据

-   [ ] 收藏状态可以切换并正确保存。
-   [ ] 点击侠客头像可打开对应详情。
-   [ ] 点击羁绊标签可打开对应详情。
-   [ ] 赛季切换后展示对应赛季数据。
-   [ ] 作者信息缺失时显示合理的缺省状态。
-   [ ] 首页不展示没有真实数据支持的统计信息。

### 测试环境

-   [ ] 微信开发者工具编译通过。
-   [ ] 至少验证一款窄屏设备和一款常见尺寸设备。
-   [ ] 验证超长阵容名、超长作者名、多个羁绊和大量侠客头像。
-   [ ] 验证收藏点击不会误触阵容详情。
-   [ ] 真机验证纵向页面滚动与头像横向滚动互不干扰。

## 10. 当前范围与后续工作

本设计稿目前定义的是首页的视觉层级、布局、交互和数据展示原则，不等同于所有功能均已完成。

建议按以下顺序推进：

1.  在微信开发者工具中实现首页结构与样式。
2.  接入真实阵容、侠客、羁绊和作者数据。
3.  实现收藏与详情弹层交互。
4.  完成超长文本和窄屏适配测试。
5.  验收通过后，再把阵容卡片规范复用到阵容列表、收藏页等相关页面。

------------------------------------------------------------------------

**设计原则总结：**
标题优先但不挤压操作区；作者靠右、收藏固定；头像独立横滑；主 C
由数据标记；羁绊自动换行并支持点击详情；不展示无真实数据支撑的统计。
